前后台降档
-
应用切到后台时，把没有显式线程规则的线程压到 e-core，省电。判据优先看系统调度组；组已被我们接管时按 oom_score_adj ≥ 900 兜底。降档优先于 S7 落点——这类线程不参与 S7 迁簇，避免「降档—迁回大核—再降档」两轮抖动。切回前台后按规则原值重算，不会停在降档值上。
Auto Assign
-
观察受管应用的线程，按角色给建议（Critical→hp-core、Latency→p-core、Worker→e-core），写入同目录 AppOpt.autocache.conf，30 天过期。只观察、不改规则：候选在「规则」页顶部，逐条采纳才会写进主配置。线程存活满 60 秒才出现，满 5 分钟标为高置信度；已有同名或通配规则覆盖的线程不再建议。
PMU 观察
-
读取硬件计数器（instructions / cycles / cache-misses），在诊断页显示受管线程的 CPI 与指令速率，用于评估 S7 的迁移是否真的划算。硬件计数器打不开、或能打开但读数恒为 0（部分厂商锁了 PMU）时，自动退到软件计时，按 CPU 时间显示线程占用，不再当成故障。只采样、不迁移：执行路径不会因为本开关改变任何一个核。需要内核允许 perf_event_open；权限不足时自动关闭，原因写在诊断页。max 128 线程、按 RLIMIT_NOFILE 预算自动收缩。
RT 实时调度
-
在「规则」页点应用右侧的 RT 按钮即可开启，参数固定为 AsoulOpt 默认：自动挑选 Critical 线程、每应用最多 2 个、RR 时间片 3 ms。全部关闭后内核时间片自动还原。RT 只在该应用的允许核心不超过 2 个时生效。
系统分组
-
系统会把应用线程划进 background 等组，该组可用核心不含规则要的大核，此时迁组和绑核都会被内核拒绝（日志记「系统分组」）。尊重：跳过并保留系统限制，省电（默认）。强制绑核（@sysgroup=takeover）：把线程拉出系统组再绑到目标核，能绑上，但后台应用也会占用大核，待机功耗会上升。
接管组归属
-
接管：首次绑定或规则变更时把线程迁进 AppOpt/<集合> 组，系统就不会再把亲和性收敛回 top-app——这是「每分钟被改写上百次」的成因。只写掩码是 2.6.1 的行为，只用于对照排查，长期使用会反复被系统冲掉。

简介

AppOpt 是一款 Android 应用 CPU 亲和性管理工具。基于规则配置文件，将指定应用的进程与线程绑定到合适的 CPU 核心（小核省电、大核高性能），配置保存后即时热加载，无需重启应用。

使用说明
  1. 规则页点击「添加」，输入应用包名，可同时配置包级默认（可选）与多条线程规则后一次保存
  2. 设置页可切换 eBPF / Proc 工作模式、cpuset 目录名、检查间隔与配置文件路径
  3. 配置文件也可直接手工编辑，保存后自动热加载
  4. 更多规则编写说明参考官网文档
